# ourly-poster

markdown で書いた記事を、ourly の管理画面に **下書き（非公開）** として保存するツール。公開はしない（公開は管理画面で人が行う）。

- 2段階で動く: ① タイトル・アイキャッチ・カテゴリだけの空の下書きを作る → ② md の本文を流し込む（何度でも上書きできる）
- カテゴリは ourly から最新の一覧を取得し、ターミナルで番号を選べる
- Mac / Windows 両対応

## クイックスタート（はじめての人向け）

### 1. Node.js をインストール

https://nodejs.org/ja から **LTS 版**（20 以上）をダウンロードしてインストールする。Mac / Windows どちらも同じページから入手できる。

### 2. このツールをダウンロード

- GitHub のこのページ右上の **Code → Download ZIP** でダウンロードし、好きな場所に展開する。
- git を使える人は `git clone https://github.com/nktnklg/ourly-poster.git` でもよい。

### 3. セットアップ

展開したフォルダの中の次のファイルをダブルクリックする。

- Mac: `setup.command`
- Windows: `setup.bat`

途中で **ourly 管理画面の URL**（例: `https://xxxx.media.ourly.jp/admin/articles`）を聞かれるので、普段使っている管理画面の URL を貼り付ける。

最後にブラウザが開くので、その画面で ourly にログインする。ログインが完了すると自動で検知され、セットアップが終わる（Enter 入力は不要。ログイン済みならブラウザは開かない）。

> **Mac で「開けません」と表示されたとき**: `setup.command` を右クリック →「開く」を選ぶ。または、ターミナルでフォルダに移動して `node setup.mjs` を実行する。

ターミナルが使える人は次でも同じ。

```bash
cd ourly-poster
node setup.mjs
```

> ログインは約30日で切れる。切れたら `npm run login` で再ログインする（各コマンドも、切れていれば自動でログイン用のブラウザを開く）。

setup はツール一式を **`~/.ourly-poster`**（Windows: `C:\Users\<名前>\.ourly-poster`）にコピーし、以降はそこから動く。ダウンロード・展開したフォルダは、セットアップ後に削除してかまわない。場所を変えたいときは、環境変数 `OURLY_POSTER_HOME` にフォルダを指定して setup を実行する。

### 4. 記事を下書き保存する

```bash
cd ~/.ourly-poster
npm run create -- "記事_本文.md"   # ① 空の下書きを作る（カテゴリを番号で選ぶ）
npm run push -- "記事_本文.md"     # ② 本文を流し込む
```

- コマンドはツールのフォルダ（`~/.ourly-poster`）で実行する。md のパスは、フォルダからの相対パスか、フルパスで指定する（ファイルをターミナルにドラッグ＆ドロップするとフルパスが入る）。
- 出力された「詳細」の URL を開くと、管理画面で下書きを確認できる。

## Claude Code / Codex から使う

### 初期設定

このツールのフォルダで Claude Code または Codex を起動し、「セットアップして」と頼む。エージェントが管理画面の URL とスキルの置き場所を聞き、setup を実行する。途中でブラウザが開くので、その画面で ourly にログインする（パスワードはエージェントに伝えない）。

### スキル ourly-poster

setup の最後に、Claude Code / Codex 用のスキル `ourly-poster` を置く場所を選べる。置いた場所で Claude Code / Codex を起動すると、「この md を ourly に下書き保存して」と頼むだけで、状態確認 → カテゴリ確認 → dry-run → 保存まで進める（保存の前に確認を求める）。ログインが切れていれば、エージェントがログイン用のブラウザを開く。

| 置き場所 | 使える範囲 |
|---|---|
| ユーザー全体（`~/.claude/skills`・`~/.agents/skills`） | どのフォルダで起動しても使える |
| ディレクトリを指定（`<dir>/.claude/skills`・`<dir>/.agents/skills`） | そのディレクトリ（記事を書くプロジェクトなど）で起動したときだけ |

あとから置く・消すときは次のとおり。

```bash
npm run skill -- --scope user                          # ユーザー全体
npm run skill -- --scope project --dir ~/works/blog    # 指定したディレクトリ
npm run skill -- --scope user --agent codex            # Codex だけ（claude / codex / both）
npm run skill -- --scope user --uninstall              # 消す
```

スキルにはツールの場所（`~/.ourly-poster`）が書き込まれる。setup を再実行すると、置いたスキルが全て更新される。

## 記事ファイルの書き方

- 本文は `<タイトル>_本文.md`、アイキャッチは同じフォルダの `<タイトル>_アイキャッチ.png` にすると、アイキャッチを自動で見つける。
- タイトルは本文先頭の `# 見出し`（H1）から取る。
- 先頭に frontmatter を書いておくと、カテゴリの選択を省ける。

```md
---
category: 📝ナレッジ共有
analysis: その他
---
# 記事のタイトル

本文...
```

- `ourly_id` は ① の成功時にツールが自動で書き込む（どの下書きに対応するかの記録）。消さないこと。

## コマンド一覧

| コマンド | 内容 |
|---|---|
| `npm run setup` | 依存のインストール・管理画面 URL の設定・ログイン・スキルの配置（`--skip-login` でログインを省略、`--skill user\|none\|<dir>` でスキルの置き場所を指定） |
| `npm run login` | ログインだけを行う（人がブラウザ画面で行う。再ログイン用） |
| `npm run doctor` | 設定・依存・ログイン状態の確認（ブラウザ画面は開かない） |
| `npm run categories` | ourly に現在あるカテゴリ一覧を表示 |
| `npm run create -- <md>` | ① 空の下書きを作成 |
| `npm run push -- <md>` | ② 本文を流し込む |
| `npm run post -- <md>` | ① → ② を続けて実行 |
| `npm run skill -- --scope ...` | Claude Code / Codex 用のスキルを置く・消す |

`node create-draft.mjs ...` のように直接実行してもよい。各コマンドは `--help` で使い方を表示する。

### オプション

| オプション | 対象 | 説明 |
|---|---|---|
| `--category <名前>` | create / post / push | 記事カテゴリ。frontmatter の `category` より優先。push では指定すると記事カテゴリを差し替える |
| `--analysis <名前>` | create / post / push | 分析カテゴリ。frontmatter の `analysis` より優先。push では指定すると分析カテゴリを差し替える |
| `--eyecatch <png>` | create / post / push | アイキャッチ画像を指定（省略時は `_アイキャッチ.png` を自動で探す）。push では指定するとアイキャッチを差し替える |
| `--force` | create / post | `ourly_id` がある md でも新しい下書きを作り直す |
| `--id <記事ID>` | push | 流し込み先の記事。省略時は frontmatter の `ourly_id` |
| `--meta` | push | タイトル（H1）・アイキャッチ・カテゴリもまとめて md から反映する |
| `--title` | push | タイトルだけ H1 から反映する |
| `--no-body` | push | 本文は更新しない（タイトル等だけ更新する） |
| `--dry-run` | 全部 | 内容を表示するだけで保存しない |

## 動きの詳細

### ① 空の下書き作成（create）

- ourly から最新のカテゴリ一覧を取得する（ourly 側でカテゴリが増えたり名前が変わったりしても追従する）。
- カテゴリは「`--category` / `--analysis` → frontmatter → `config.json` の `defaults`」の順で決める。無い、または一覧に無い名前のときは、ターミナルに番号付きの一覧が出るので番号で選ぶ。選んだ名前は frontmatter に保存される。
- ターミナル入力ができない環境（AI エージェントからの実行など）では、候補一覧を表示してエラーで止まる。`npm run categories` で候補を確認し、`--category` / `--analysis` で指定する。
- 絵文字の表記ゆれは同じ扱いにする（`⭐️お知らせ` と `⭐お知らせ`）。
- `ourly_id` がある md では二重作成防止のため止まる。本文の修正は ② で反映する。
- `--dry-run` でも、カテゴリ取得のため ourly に接続する（読み取りのみ）。

### ② 本文の流し込み（push）

- md の本文を ourly のエディタ形式に変換し、①で作った下書きの本文だけを差し替える。タイトル・アイキャッチ・カテゴリはそのまま。
- タイトル・アイキャッチ・カテゴリも変えたいときは `--meta`（まとめて md から反映）、または `--title` / `--eyecatch <png>` / `--category` / `--analysis` で項目ごとに指定する。本文を変えずにこれらだけ更新するときは `--no-body` を付ける。
  - 例: `npm run push -- 記事_本文.md --meta --no-body`
  - `--dry-run` と一緒に使うと、ourly から現在の値を読み取って（保存はしない）変更前後を表示する。
- 何度実行しても同じ下書きが上書きされる。
- 公開済み・公開予約済みの記事は更新しない（エラーで止まる）。

### 本文変換の対応

| markdown | 変換結果 |
|---|---|
| `# 見出し` | 記事タイトル（先頭の H1） |
| `## 見出し` など | 見出しブロック |
| 段落 | 段落ブロック（段落内の改行は保持） |
| `**太字**` / `*斜体*` | 太字 / 斜体 |
| `[リンク](URL)` / 素の URL | リンク |
| `> 引用` | 引用ブロック（引用内のリストは `・` 付きの行） |
| `---` 水平線 | 区切り線 |
| 箇条書き / 番号付きリスト | リストブロック（入れ子も保持） |
| `![キャプション](画像)` | 画像ブロック（alt がキャプションになる） |

### 本文の画像

- `![キャプション](images/photo.png)` のように書く。相対パスは md のフォルダが基準。絶対パスや `https://` の URL でもよい。
- 形式は png / jpg / jpeg / gif（ourly のエディタと同じ）。
- パスに空白があるときは `%20` にするか `![説明](<images/my photo.png>)` のように `<>` で囲む。
- 文中に画像を書くと、その前後で段落が分かれる。見出し・リスト・引用の中の画像は入れられないので、警告を出して省く。
- ファイルが無い・形式が対応外のときは、保存する前にエラーで止まる（`--dry-run` でも確認できる）。
- アップロードした画像は `cache/uploaded-images.json`（git 管理外）に記録し、同じ内容の画像は次回の push で再利用する。

### ログイン

- ログイン状態はツール専用のブラウザプロファイル `auth/profile/` に保存される（普段使いの Chrome とは別）。
- セッションの有効期限は約30日。切れているときは、各コマンドが自動でログイン用のブラウザを開き、ログインするとそのまま処理を続ける（最大5分待つ）。
- 同時に2つのコマンドは実行できない（`auth/profile.lock` で排他）。
- `config.local.json` に `"browserChannel": "chrome"` を書くと、同梱の Chromium の代わりにインストール済みの Google Chrome を使う。

## 更新するとき

- ZIP で入手した場合: 新しい ZIP を展開し、そのフォルダで `setup` を実行する（ダブルクリックでよい）。
- git の場合: `git pull` → `npm run setup`。
- どちらも `~/.ourly-poster` が新しい版で上書きされる。ログイン状態（`auth/`）・管理画面の URL とスキルの記録（`config.local.json`）・画像のキャッシュ（`cache/`）は残り、置いたスキルも更新される。

## 安全上の注意

- 常に **非公開の下書き** として保存する。このツールは公開・公開予約をしない。
- 記事の削除は管理画面から手動で行う（このツールは作成と更新のみ）。
- パスワードはツールでは扱わない。ログインは必ずブラウザ画面で本人が行う。
- `auth/`（ログイン状態）と `config.local.json`（管理画面 URL・スキルの置き場所）は各自の環境専用。共有・コミットしない（`.gitignore` 済み）。
